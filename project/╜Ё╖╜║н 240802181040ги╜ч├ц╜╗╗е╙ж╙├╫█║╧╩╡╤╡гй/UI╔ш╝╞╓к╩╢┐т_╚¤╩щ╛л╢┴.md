## 1. 设计师能力模型（三书汇总）

一个网页/移动端 UI 设计师的工作可拆成 6 层能力，缺一层就会出现"好看但不可用/可用但难交付"：

1. **信息层**：信息架构、内容优先级、用户与业务目标（A §3.1；B §2.1；C §1.2.1）
2. **结构层**：草图 → 交互原型 → 线框图 → 栅格系统（B §2.3–2.5；C §1.2.2）
3. **视觉层**：字体、色彩、留白、图标、图片、风格（A §2、§4；B §4.7–4.9、§5.2）
4. **规范层**：安全宽度、首屏高度、栅格、字号行高、命名、标注（B §4、§5）
5. **体验层**：可用性、可寻性、可信、无障碍、一致性、反馈（B §6）
6. **交付层**：切图、导出格式与倍率、标注文档、共享评审（B §1.2、§4.10；C §6）

### 1.1 八种网页设计风格（A §1.5）
| 风格 | 特征 | 适用 |
|---|---|---|
| 拟物化 | 模拟真实材质、光影、纹理 | 需要直观隐喻、仿真操作 |
| 扁平化 | 去高光阴影、纯色块、几何化 | 信息密度高、加载快、通用 |
| 极简化 | 极少元素、大留白、单一焦点 | 品牌展示、内容型产品 |
| 3D | 立体建模、透视与光影 | 科技、游戏、产品发布 |
| 插画 | 手绘/矢量插画主导 | 个性化品牌、年轻用户 |
| 无边框 | 去掉卡片/模块边框，用留白分区 | 现代简约、内容流 |
| 纵向分割 | 竖向分栏切割页面 | 多栏目、杂志化排版 |
| 超级版头 | 超大首屏视觉/巨幅标题 | 品牌首页、活动专题 |

A 的制作流程五段：前期策划 → 交互设计 → 视觉设计 → 开发测试 → 运营维护（与 C §1.2 的五阶段同构，B 则给了更细的 8 步操作流）。

## 2. 设计流程

### 2.1 产品级 5 阶段（C §1.2）
需求分析 → 交互原型设计 → 视觉界面设计 → 开发测试 → 发布运营。

- **需求分析**：市场分析、用户需求分析、竞品分析、产品功能设计、功能技术分析 → 输出需求文档。
- **交互原型**：交互原型 + 页面流程 → 功能流程 → 低保真模型 → 高保真模型 → 产品原型说明文档。
- **视觉界面**：视觉概念稿（出 2–3 套风格供选，定风格再深化）→ 视觉设计图（风格 + 完善界面 + 动画特效 + 评估具象化 + 设计系统）→ 标注切图 → 适配打包。
- **标注内容**（C §1.2.3）：边距、间距、控件长宽、控件颜色、背景颜色、字体、字号、字体颜色。

### 2.2 项目级工作流（B §2、§7）
1. **准备工作**：软硬件（Photoshop 必备、Dreamweaver 协作、Illustrator 出 SVG、双屏/手机/平板做真机测试）、浏览器（Chrome/Safari/Firefox/IE Tester）、环境与版权意识、知识储备（软件/编程/UX/交互/移动/运营）。
2. **理解产品**：把产品完整用一遍；与客户深度沟通（"做 PSD 几天，沟通理解可能半个月"）。
3. **草图（纸笔）**：不确定就先画，便于改、便于沟通（B §2.3）。
4. **交互原型图**：用 PSD 做分屏示意图，用简单形状/色块替代可变内容，可加注释，用来过稿（B §2.1.2）。注意区分：原型 ≠ 原型图 ≠ 交互原型图。
5. **线框图**：布置内容与功能，定结构、层级、比例；直接沿用为视觉稿底稿，减少重复设计（B §2.1）。
6. **视觉设计**：按规范做字体、色彩、留白、图标、图片处理（B §7.7）。
7. **标注与切图**：标尺寸/间距/颜色/字体，导出 PNG/SVG，记录 CSS 数值给前端（B §1.2.2–1.2.3）。
8. **开发协作与真机验证**：响应式断点、@2x 图、Retina 清晰度。

### 2.3 线框图 vs 原型图 vs 效果图（B §2.1）
| | 线框图 | 交互原型图 | 效果图 |
|---|---|---|---|
| 使用阶段 | 视觉设计阶段的框架、信息分布、规范 | 视觉设计前期的模型、人机交互构想 | 视觉设计成果 |
| 特点 | 直接用于视觉设计，提高质量与效率 | 适合与客户/团队沟通，快 | 包含品牌、文本、导航、色彩、字体、布局、体验 |
| 工具 | Photoshop | Photoshop + PSD 模板 | Photoshop |

**警示**：不建议用原型工具直接生成代码，定制化需求高、返工多（B §2.1.2）。

### 2.4 自适应 vs 响应式（B §2.2）
- **AWD 自适应**：针对设备，可能为移动端减内容、用不同 URL 前缀（如亚马逊、淘宝）；制作与维护成本高，速度有优势。
- **RWD 响应式**：针对尺寸，只改变元素布局外观，同一 URL，SEO 友好，仍是主流。
- 记忆法：Adaptive=Devices，Responsive=Dimensions。

## 3. 尺寸与版式规范（B §4.2–4.6，核心量化部分）

### 3.1 屏幕尺寸与分辨率（B §4.2 表4-1）
PC/平板常见分辨率与全球占比（2017.01 W3C 数据）：1024×768、1280×1024、1280×800、1366×768（35%）、1920×1080（17%）、2560×1440 及以上。

手机常见分辨率（DeviceAtlas 2016）：240×320、320×480、480×800、480×854、540×960、640×960、640×1136、720×1280、750×1334、1080×1920、1440×2560、2160×3840。
**设计稿常用参考值：750×1334、1080×1920。**

### 3.2 页面安全宽度（B §4.3 表4-3）
| 分辨率 | 安全宽度范围 | 推荐宽度 | 推荐首屏高度 |
|---|---|---|---|
| 1024×768 | 980–1002 | 980 | 548 |
| 1280×800 | 1190–1200 | 1190 | 580 |
| 1366×768 | 1200–1331 | 1200 | 548 |
| 1440×900 | 1200–1405 | 1200 或 1331 | 680 |
| 1920×1080 | 1200–1405 | 1200 或 1331 | 855 |
| 2560×1600 | 1689–1885 | 1689 | 1220 |

- 基于 Bootstrap 3.x 时取 **1170px**；Bootstrap 4.x 取 **1200px**。
- 首屏高度只以 Chrome 为基准（扣除标签栏、菜单栏、书签栏、状态栏）。

### 3.3 画布、首屏与全屏图（B §4.2.2、§4.4）
- 案例画布：**1920×5000px**（单页长图，便于整体观察结构）。
- 首屏参考线：**768px**；内容安全高度：**560px**（1366×768 场景）。
- 全屏图导出 **1920×1080px**，但在页面中按剪贴蒙版裁切后可视约 1920×768，保证核心内容不被矮屏裁掉。
- 全屏图尺寸/首屏参考线/安全高度对照（B 表4-4，单位 px）：1280×850→850/620；1366×768→768/560；1680×1050→900/710；1920×1080→1080/855（常用）；2560×1600→1600/1220；2880×1800（常用于 Retina）。表中另列有 1440×900、1920×1200 两组常用图片尺寸。
- 单位：Web 稿用**像素**，PSD 分辨率 **72 像素/英寸**；Retina 屏不要用 300dpi，否则前端尺寸对不上；图标/形状能用矢量就用矢量，图片尽量出 **@2x**。

### 3.4 栅格系统（B §4.5）
- 12 列（12 栅栏）：列宽 **70px**，沟槽 **30px**，内容区 **1170px**（70×12 + 30×11 = 1170 ✔）。
- 1920 宽文档中，安全区左右留白 =(1920−1170)/2 = **375px**。
- Photoshop：视图 → 新建参考线版面，填列数 12、沟槽 30。
- 作用：节奏感与空间感、天然黄金比例、提高设计-开发协作效率、可作为前端代码的对齐标准。

### 3.5 页面组成模块（B §4.6 表4-5，中英对照）
Navigation 导航 / Header 页头 / Body 内容主体 / Page Title 页面标题 / Breadcrumb 面包屑 / Footer 页脚 / Logo or Identity 标识 / Copyright 版权。

### 3.6 字体规范（B §4.7；A §2.1.2）
- **中文安全字体**（优先级从上到下）：Windows：微软雅黑（Win7+）> 黑体 SimHei > 宋体 SimSun > 新宋体 > 仿宋 > 楷体；macOS：苹方 PingFang SC > 冬青黑体 Hiragino Sans GB > 华文细黑 STHeiti Light/STXihei > 华文黑体 > 华文楷体 > 华文宋体 > 华文仿宋。
- **英文安全字体**：无衬线 Helvetica（最安全）> Arial > Tahoma > Trebuchet MS > Verdana > Arial Black > Impact；衬线 Courier > Courier New > Georgia > Times > Palatino > Garamond > Bookman；等宽 Menlo/Monaco/Consolas/Courier。
- **CSS 字体栈**：
  - 英文：`"Helvetica Neue", Helvetica, Arial, sans-serif`
  - 中文：`"PingFang SC", "Hiragino Sans GB", STXihei, "Microsoft YaHei", SimSun, SimHei`
  - 中英混排：`-apple-system, "PingFang SC", "Hiragino Sans GB", "Helvetica Neue", Arial, "Microsoft YaHei", "WenQuanYi Micro Hei", sans-serif`
- **字号**（B 表4-9，body=14px 基准）：h1 4em、h2 2.8125em、h3 2em、h4 1.4375em……；正文行高 1.25–1.5。**正文字号最小值 12–16px 区间**（B 结论：12–16px 为提高可读性的最小取值区间）。
- **PC 端字号规范（A 表2-1）**：导航/标题 16/18/20/24/30px；正文 14px；最小 12px；特殊强调 36/40/48px。
- **移动端字号（A §2.1.1）**：每行 30–40 个字符；iOS 正文最小 24px（按 750 稿口径）；行距为字号的 120%–150%（A §3.4 第 7 点）。
- **字体数量**：同一网页 ≤ 4 种（A §2.1.1）；MDL 场景全站以 Roboto 为主，避免花哨（B §8.2.1）。
- **MDL 字号表（B 表8-1）**：body 14px、h1 56px、h2 45px、h3 34px、h4 24px、h5 20px、h6 16px，字重 400/500，字距 −0.02em~0.04em。

### 3.7 布局规范（B §4.8）
- 文字：由上至下、由左至右（阿拉伯文/波斯文例外）。
- 图片比例：4:3（800×600）、16:9（1280×720 / 1920×1080 / 2560×1440）、16:10（1280×800 / 1920×1200 / 2560×1600）。
- 感官布局：第一眼印象，受网格布局方式影响。
- 透视布局：一点/两点/三点透视，制造空间感。

### 3.8 留白（B §5.2；A §3.4 八点）
B 的 5 个作用：导航与内容清晰、增强图文可读性、建立平衡布局、减少视觉疲劳、给元素可持续空间。
A 的 8 个关键点：
1. 留白可以是任意颜色（=负空间，不是白色）。
2. 仅保留必需的 UI 元素。
3. 保证视觉焦点**只有一个**。
4. 留白要有疏密感与节奏感。
5. 图片比文字更抢注意力（想让文字为主时，别在周围放图片）。
6. 文案直接简洁，短文案在留白衬托下更有力量。
7. 控制文本易读性：**行距 = 行高的 120%–150%**，字间距也算留白。
8. 留白量与品质感正相关（但不等于越多越好）。

### 3.9 页脚（B §5.3）
标准组件（中英）：Site Map 网站地图 / About、Contact 关于与联系 / Contact Form 留言表单 / Back to Top 返回顶部 / Follow Us 社交入口 / List 列表（最新发布、归档、标签）/ Logo / Navigation 导航（隐私政策、服务条款）/ Subscribe 订阅 / Authorship Information 原创声明 / Copyright 版权。
体验目标：建立必要导航、模块间留白适当、表单不复杂、首尾呼应、突出品牌、列表分栏美观、保留快速互动入口。
两种方案示例：①联系方式+版权（简化）；②联系方式+版权+灰色 Logo+社交（信息多元、与头部呼应）。

### 3.10 命名规范（B §5.5）
- 图片：`people.jpg` → `people-boy.jpg` → `people-school-boy.jpg` → `people-job-boy-f.jpg`（复合词+一级属性+二级属性）；`people@2x.jpg` / `@3x`；分隔用中划线或下划线，全小写。
- 文件夹：`assets`（含 images/css/js/fonts）、`images`/`img`、`fonts`、`icons`、`css`、`sass`、`js`、`core`、`functions`、`themes`、`plug-ins`、`admin`、`documentation`、`licensing`、`demo`。
- 规则：PSD 文件与图层可用中文，**导出后的图片和文件夹一律英文**（避免编码 bug）。

## 4. 元素设计（A §2；B §5.4）

### 4.1 文字
- 字体性格：笔画粗壮棱角分明=男性、庄重、有力；纤细圆润=女性、清新、精密；手写体=随性、个性。
- 字体数量 ≤ 4 种；尽量用标准字体（用户设备未必有你选的字体）。
- 行宽：太长易串行，太短破坏节奏；移动端每行 30–40 字。
- 避免大段全大写（降低阅读效率）。
- 图形化文字可承载语言之外的信息（大小、曲直、疏密都影响感受）。

### 4.2 图片
- 格式：**JPEG**（有损、连续色调、全彩、照片）、**PNG**（可移植网络图像、支持透明、图标/图形）、**GIF**（无损、压缩率约 50%、颜色简单时极高、动画）。
- 颜色模式：RGB（24 位真彩、1677 万色，屏幕用）、CMYK（印刷，PS 部分功能不支持）、Lab（色域最广）、灰度（8 位、254 级）。
- 输出：`文件→导出→存储为 Web 所用格式`；JPEG 品质默认 75；PNG 选 24 位（png-24）；导出后再用 ImageAlpha/PNGoo/TinyPNG 压缩（通常可减 50%–75%）。
- 矢量：SVG；需要 SVG 动画时用 Illustrator 导出（PS 与 AI 算法有差异）。

### 4.3 图标
- 广义（指代性图形符号）与狭义（软件/系统图标）。
- iOS 图标尺寸（A 表2-2，按 iPhone 6 Plus / iPhone 5·6·7·8 / iPad mini）：App Store 1024；应用 180/120/90；主屏幕 114/114/72（原文如此，存在重复，实际以系统规范为准）；搜索 87/58/50；标签栏 75/75/25；工具栏/导航 66/44/22。
- Android（以 1080×1920 为基准）：启动图标 144×144，上下文图标 96×96，系统通知 48×48，通知 72×72；单位 dp/sp（1dp≈160ppi 下的 1px，sp 随用户字号缩放，通常 sp=dp）。
- Material 启动器图标可 512/256dp，操作栏 32dp，通知 24dp，小图标 16dp（B 引最新 MD 规范）。
- 设计方法：形状工具绘制、统一风格（造型规则/圆角/线宽/配色），底部加"底衬"控制可点击范围；前端优先 SVG 或图标字体，其次透明 PNG。
- MDL：图标网格绘制笔画 2px（Android 2dp），曲线、角度、内外描边统一 2px。

### 4.4 按钮（A §2.3.3 七条）
① 形状一眼看懂、不与背景融合；② 加阴影增强识别（极简风格可不加）；③ 让用户一眼判断功能；④ 尺寸随屏幕（移动端与 PC 端不能同尺寸）；⑤ 保持形状一致性（矩形与矩形、圆角与圆角）；⑥ 用对比色区分主/次/中性操作；⑦ 类型：普通按钮、图标按钮、文字按钮。

### 4.5 Logo（A §2.4）
- 三种表现形式：特定图标（表象符号，独特醒目但关联间接）、特定文字（表意符号，含义直接但易混）、合成文字（图文结合，网页 Logo 的主流事实规范）。
- 规范要点：标准色、背景配色体系、反白稿、最小显示尺寸、特定条件配色/辅助色；文字与图标边缘清晰、不交叠；考虑竖排与作为背景的排列。
- 动态化：只做成比例缩放/移动，不做翻滚、倾斜等破坏性变形。
- 原则：多样统一、突出支配性要素；兼顾纸媒单色/反白、织物、车体、立体墙面等应用。

### 4.6 导航（A §2.5）
主导航常见位置：顶部、左侧、右侧；导航要直观明确，尽量降低用户寻找成本；页脚导航是补充。

## 5. 版式与移动端布局（A §3）

### 5.1 信息结构 → 布局
布局的基础是信息结构；信息结构的两类目的：①分类并系统化（按种类/价位）；②重要信息优先（按时间与重要度）。布局操作顺序（A §3.1.2）：整理用户意见 → 划分用户类别 → 明确建站目的 → 整理内容并结构化（层次/超链接/数据库）→ 分类并检验导航功能 → 确定标记体系 → 分页面放置元素。

### 5.2 七种常见 PC 布局（A §3.2）
| 布局 | 结构 | 优点 | 缺点 |
|---|---|---|---|
| "国"字型 | 上标题+Banner，左主菜单、中主内容、右次要，下版权 | 充实、信息量大 | 拥挤、不灵活 |
| 拐角型（T 字型） | 上+左/右结合，右侧为主内容 | 结构清晰、主次分明、易用 | 呆板、易乏味 |
| 标题正文型 | 上标题、下正文 | 适合文章页/注册页 | 信息承载有限 |
| 左右分割型 | 左导航、右正文 | 一目了然 | 导航区受限 |
| 上下分割型 | 上 Logo+导航、下正文 | 结构简单 | 首屏易浪费 |
| 综合型 | 左右+上下组合 | 承载复杂信息 | 复杂度高 |
| 封面型 | 整屏视觉+少量链接/进入 | 赏心悦目，适合品牌首页 | 信息量小 |

### 5.3 布局的艺术表现（A §3.3）
- 分割构成：等形分割（整齐）、自由分割（活泼）。
- 对称构成：左右对称、回转对称（反射/移动后旋转一定角度）。
- 平衡构成：对称平衡（中轴）、非对称平衡（无中轴但视觉稳定，难度高）。

### 5.4 移动端尺寸与组件（A §3.5）
- **iOS**：以 iPhone 6（**750×1334px**，即 375×667pt @2x）为基准设计，输出 @1x/@1.5x/@2x/@3x 适配；单位 px（屏幕像素）与 pt（1pt=1/72 英寸≈0.35mm，iOS 字体单位）。
- **Android**：以 **1080×1920px** 为设计稿基准（向上向下适配幅度最小）；单位 dp（长度）与 sp（字体，通常 sp=dp）。
- 组件分区：状态栏、导航栏、标签栏、内容区（iOS/Android 均如此），各栏高度必须严格按规范，否则适配出错。
- **边距**：全局边距常用 32/30/24/20px，**必须为双数**（iOS 设置页 30px，网易 UI 24px）；卡片间距最小 ≥16px，常用 20/24/30/40px（iOS 设置页 38px、部分页 70px 的差异说明"间距随信息密度变化"）。
- 邻近性原则（格式塔）：距离近的元素被视为一组；图标与文字间距应小于文字与相邻图标的间距。

### 5.5 四种移动端布局（A §3.6）
| 布局 | 特征 | 优势 | 局限 | 关键数值 |
|---|---|---|---|---|
| 列表式 | 上下滑动、层级清晰 | 快速浏览大量条目 | 灵活度低、易疲劳 | 列表舒适最小高度 **80px** |
| 陈列馆式 | 网格但可不等分、流动性强 | 同高度容纳更多入口 | 不适合顶层框架、易杂乱 | — |
| 宫格式 | 一行三列 | 符合习惯与黄金比例、易适配 | 需回初始点、层级路径深 | — |
| 卡片式 | 卡片独立、信息量大于列表 | 突出核心内容、减少跳转 | 入口过多时笨重 | 双栏卡片常用于图片主导型 App |

### 5.6 页面分割的 6 种手法（B §3.2）
斜线/三角形/不规则组合、圆弧与矩形相交、波浪线分割、矩形重叠（视差对齐）、等分矩形排列、平缓重复曲线。作用：场景感、故事性、黄金分割、秩序与层次。

### 5.7 5 种网格结构（B §3.1.2）
单列（长文/海报/全屏）、双列（博客，可等宽或比例分栏）、多列（瀑布流/杂志/图片展示）、模块（等距方格，适合表格/日历/图标/复杂排版）、层级（横向分层，适合产品功能页/单页网站）。
**注意区分**：网格结构=信息组织方式（知识）；网格系统=12 列工具（设计手段）；一个 12 列系统可表现为多种结构。

### 5.8 绘制网格前的 7 项评估（B §3.1.3）
目标用户群体、界面功能性、素材复杂性、度量单位、屏幕分辨率与尺寸、字体、模块顺序。

## 6. 配色（A §4；B §4.9）

### 6.1 基础概念
色相（H）、明度（V）、纯度/饱和度（S）、可视性（纯度越高、对比度越大越可视）。
色环：12 色；对比色/补色=相距 180°；类似色=相邻、夹角 ≤60°；冷暖色以绿、紫为界；无彩色=黑白灰（只有明度属性）。
三原色：RGB（光源/屏幕，加法混合）；CMY/RYB（反射光/颜料，减法混合）；CMYK 的 K 取 black 末字母以避免与 Blue 混淆。

### 6.2 颜色模式与十六进制
RGB 24 位（三通道各 8 位，1677 万色）；CMYK（印刷，色域小于 RGB）；Lab（色域最广）；灰度（8 位，254 级）。
十六进制：`#RRGGBB`，每两位一个通道；0–9 调暗、A–F 调亮；`#000000` 明度/饱和度全失，`#FFFFFF` 最大；三值相近=低饱和，最大通道决定色相，最大值决定亮度，最小值决定饱和度。
**Web 安全色**：PS 拾色器勾选"只有 Web 颜色"。

### 6.3 四类配色要素（A §4.2）
主题色（中心色、构成视觉中心）、背景色（支配色，面积最大，可为白/纯色/渐变/图像）、辅助色（陪衬，按钮图标等小元素，可为单色/单色系/组合）、强调色（与主题色强对比，用于视觉焦点）。

### 6.4 五种基础配色方法（A §4.3）
单色（同色加白/黑变化明度）、类似色（12 色环夹角 ≤60°）、补色（180°，强烈醒目）、邻近补色（补色+其相邻 1–2 色）、无彩色（黑白灰）。

### 6.5 文字与链接配色（A §4.4）
背景偏纯/低明度、文字偏亮色以保证对比；有背景图时需考虑可读性。
链接 4 状态：默认、悬停、选中、已访问——为省时可只配 2 种颜色（默认深灰 + 悬停橙）。

### 6.6 配色技巧（A §4.6）
**突出主题**：明确焦点（直接强化 vs 间接强调）、提高主题区饱和度、增大明度差、增强色相（用互补）、抑制辅助色/背景。
**整体融合**：接近色相、统一明度、接近色调、添加类似色/同类色（颜色数控制在 2–3 种）、渐变产生稳定感与节奏。
**偏色调整（A §4.9 引 B）**：偏黄→减黄；偏红/品→加青减品；偏紫→加黄减品（多蓝少红）；偏绿→加品；偏暗→加白。
**色彩心理学（B 表4-10，西方文化）**：红=刺激/危险/饥饿；橙=活力/友好/冒险；棕=泥土/舒适/可靠；黄=太阳/快乐/财富/警戒；绿=自然/生长/安全/新鲜；蓝=天空/平静/可靠/智慧；紫=神秘/财富/怀旧；白=纯粹/安宁；灰=正式/冷淡/技术/精确；黑=支配/虚无/死亡/优势。

### 6.7 MDL 调色板与色彩比例（B §8.2.2）
用 Google 官方调色板选主色，其他作高亮/辅助；统计整页色彩比例（按面积排序）自检是否单调或疲劳；相似色+少量对比色可避免单调。

## 7. 网页广告设计（A §5）

- 广告特征：传播工具、说服性、有目的有计划且连续、对广告主与用户都有价值。
- 选型原则：与页面环境契合（不突兀、不破坏和谐）；顶/底 Banner 适合工具类；视频类适合贴片/暂停插屏；图文信息流适合资讯、社交、视听。
- **Banner 广告常见尺寸（A §5.2.1）**：640×100、320×50、728×90、1280×720、640×288、300×250（px）。
- 移动端 5 类：Banner（首/发现/专题页顶底中部）、开屏（启动加载，尺寸最大、品牌主青睐，可全屏/半屏，静态/GIF/多帧）、信息流（小图/大图/组图/竖版）、插屏（暂停、过关、跳转、退出时，半屏/全屏，可点可忽略）、视频贴片。
- PC 端 5 类：文字广告、Banner、对联式浮动、网页漂浮、弹出广告。
- PC 广告 6 特点：传播范围广、创意感官强、直达核心消费群、节省成本、互动性强、效果可统计。

## 8. 用户体验（B §6）

### 8.1 核心
UX = 使用某产品/系统/服务时的行为、态度与情绪；UED 更侧重技巧与过程；UCD 以用户为中心。
信息架构三要素平衡：**User（用户）—Content（内容）—Context（上下文）**（Peter Morville）。
7 要素蜂窝：Useful 有用、Usable 易用、Desirable 期望值、Findable 可寻、Accessible 无障碍、Credible 可信、Valuable 有价值。

### 8.2 提升体验的 10 种方式（B §6.2）
1. 减少不必要的交互动画（过度动画增加思考与延迟）。
2. 增加对比度、提高可读性（文字与背景、导航链接在不同底色下加圆角背景）。
3. 运用留白（聚焦、呼吸感）。
4. 减少页面加载时间（PNG 压缩 50%–75%；延迟 2–3s 放弃率可高达 80%；关注图片、服务器响应、静态资源压缩、CDN、缓存、登录重定向、资源加载顺序）。
5. 有吸引力的视觉引导（图标+悬浮提示、语义图标、表单引导）。
6. 超链接差异化（导航/列表/侧栏/底部导航各自区分；后台横纵导航用不同风格）。
7. 合理使用图像（优先客户授权高清图，加工合成提升转化）。
8. 保持风格元素一致性（导航、字体、标题、色彩、按钮、插图；PC 与移动端继承图形比例、文本色、高亮色、圆角）。
9. 优化 404 页面（统一风格、搜索框、推荐、趣味插画，减少挫败）。
10. 满足响应式需求（按前端规范约束设计，按需出多尺寸版本）。

## 10. 实战方法论（B §7 完整案例）

案例：为"帆布鞋/街头文化"个人网站做从 0 到 1 设计（非 Redesign）。步骤与要点：
1. **项目分析**：用 SWOT 等分析方法约束设计重心（不要堆理论，选适合项目的）。
2. **目标设定**：原创性、细节与代码质量、个人风格与技术表现力、以自有网站为主体、敢于研究趋势、满足细微响应式、跨设备兼容。
3. **草图**：从产品/客户素材中提炼符号（如红色鞋带 → 主色红），先纸笔后软件。
4. **配色方案**：主色红，"红色必须把握度"以免视觉疲劳；用 Adobe Color Themes 生成关系（二次色/互补/复合/单色/阴影），再入色板。
5. **线框图**：画布 1920×1080；判定用 1366×768 浏览器无横向滚动条；安全宽度 1200（不用 Bootstrap）；首屏线 700px 可视高度；导航 1200×84 圆角矩形；内容主体 1920×257 色块承载时间轴；表单用线条风格；页脚 1920×192 黑色色块。
6. **效果图（视觉设计）**：首屏色块→置入图片（高斯模糊+透明度）→剪贴蒙版混合（色相/饱和度层 + 强光/柔光半透明层）→细节（1920×5px 线条）→头像模块（正圆剪贴蒙版+社交图标）→主视觉（大字 Welcome+线条+向下箭头）→第 2 屏文字模板（段落样式）→时间轴排版→作品模块（11 个图层组合）→留言表单（1px 箭头风格）→页脚（低透明度风景图+1920 色块+15px 圆角订阅按钮）。
7. **移动端**：在 PC 稿基础上做，不重复设计；用纸笔先出思路。

可复用的"细节手法清单"：1px 箭头贯穿全站形成风格、剪贴蒙版统一色调、强光/柔光半透明层调氛围、正圆裁切头像、低透明度图片做页脚纹理、圆角与直角混用需有规则。

## 11. Adobe XD 工具链（C）

### 11.1 工作界面
菜单栏、工具栏、模式栏（设计/原型/共享）、属性面板、工作区域（画板+粘贴板）、图层面板、资源面板。

### 11.2 基本操作
新建（预设 iOS/Android/Web 尺寸）、打开/导入、保存（本地文档/云文档）、画板创建与管理（预设尺寸、复制、命名）、撤销/重做、文档历史记录、参考线（手动/智能）、网格定位。

### 11.3 原型与 UI 设计能力

### 11.4 交互原型（C §5）
- 触发条件：点击、拖移、时间（可设延迟秒数）、按键和游戏手柄（PC/游戏 UI）、语音。

- 动画参数：缓动、持续时间、保留滚动位置等；可为同一对象添加多个操作。
- 叠加：适合弹窗、菜单、浮层；触发固定为点击。
- 锚点链接：长页面内跳转。
- 定时过渡：自动轮播/引导页。
- 预览：桌面播放器、Web 浏览器、真机（iOS/Android）。

### 11.5 输出、标注与共享（C §6）
- 导出对象：对象/组/组件/画板/整个画布；命令：批处理、所选内容、所有画板、整个画布、After Effects。
- 格式：PNG（设计=1x；Web=1x/2x；iOS=1x/2x/3x；Android=ldpi~xxxhdpi）、SVG、PDF、JPG。
- 命名：导出资源名沿用 XD 中元素/画板/文件名。
- 标注：用 PxCook 标注（边距、间距、控件长宽、颜色、字体字号字色），支持 px/dp 互转。
- 共享：生成共享链接（团队/客户可评论、查看交互），可发布设计规范与交互原型。
- 提示：切片尺寸建议双数（C §6.6.1）。

### 11.6 iOS/Android 设计尺寸对照（C 表4-1）
| 机型 | 设计像素 | 开发像素 | 倍率 |
|---|---|---|---|
| iPhone SE | 640×960 | 320×480pt | @2x |
| iPhone 5/5S/5C | 640×1136 | 320×568pt | @2x |
| iPhone 6/6s/7/8 | 750×1334 | 375×667pt | @2x |

## 12. 三本书的交叉校验与差异

| 主题 | A 的说法 | B 的说法 | 结论 |
|---|---|---|---|
| 画布基准 | 未系统给 PC 画布 | 1920×1080，安全宽 1170/1200 | 以 B 为准（有推导链） |
| 栅格 | 只讲"三栏/参考线" | 12 列 70px+30px 沟槽=1170 | B 可量化为代码参数 |
| 正文字号 | 14px，最小 12px | body 14px，最小 12–16px | 一致 |
| 移动端基准 | iOS 750×1334、Android 1080×1920 | （B 主 PC，移动端仅表格） | 以 A/C 为准 |
| 移动端边距 | 32/30/24/20，必须双数；卡片间距≥16 | 只讲留白原则 | A 给数值，B 给原则 |
| 配色方法 | 单色/类似/补色/邻近补色/无彩色 | 单色/类比/互补/分裂补色/二次色（工具口径） | 术语不同，逻辑一致 |
| 图标规范 | iOS/Android 具体尺寸 | MDL 2px 笔画 | 平台规范 vs 风格规范，互补 |
| 流程 | 5 阶段（C 更细） | 8 步项目流（含沟通、切图、标注） | B 更贴近真实项目 |

**OCR 可信度提示**：正文叙述类内容识别准确；表格中的个别单元格（如 iOS 图标同尺寸重复、A 配色方案色值）存在识别误差，实际使用时应以官方平台规范（Apple HIG / Material）复核。

## 14. 后续工作可直接调用的检查清单

**做页面前**
- [ ] 明确用户、目标、内容优先级（信息结构）
- [ ] 定画布：PC 1920×1080（安全宽 1170/1200）；移动 iOS 750×1334 或 Android 1080×1920
- [ ] 建 12 列栅格（70+30，总 1170）或等距模块网格；左右留白 375（1920 稿）
- [ ] 定首屏线（768）与内容安全高度（560/855）

**做页面中**
- [ ] 字体 ≤4 种，只用安全字体；正文字号 ≥12px（PC）/≥24px（移动 750 稿），行高 1.2–1.5
- [ ] 配色 ≤3 主色：主题/背景/辅助/强调各就位；链接 4 状态（至少 2 色）
- [ ] 留白单一焦点、疏密有节奏、行距 120%–150%
- [ ] 移动端边距用双数（20/24/30/32），卡片间距 ≥16
- [ ] 图标统一线宽/圆角/配色；按钮 7 条原则自检
- [ ] 命名：图层可中文，导出资源全英文、@2x/@3x

**交付前**
- [ ] 标注：边距、间距、控件尺寸、颜色、字体字号字色
- [ ] 导出：PNG 1x/2x/3x、SVG 矢量、JPG 品质 75、PNG 再压缩
- [ ] 体验自检：动画是否过度、对比度是否足够、404、一致性、响应式断点
- [ ] 共享链接 + 交互原型走查
